Technical Deep-Dive: HTTP Client-Server Communication

How modern web browsers exchange structured requests and responses with web servers over HTTP/1.1 and HTTP/2

1. HTTP Request Methods

  • GET: Retrieves resources (e.g. fetching destination photos). Must be idempotent and safe without payload.
  • POST: Submits data to be processed (e.g., booking form submission). Carries data in the message body.
  • PUT: Replaces entire target resource with uploaded payload.
  • DELETE: Removes specified resource from the server.
  • HEAD: Same as GET, but retrieves only headers without response body.

2. Request & Response Headers

Client Request Headers:

POST /booking.php HTTP/1.1
Host: localhost
User-Agent: Mozilla/5.0 (Windows NT 10.0)
Content-Type: application/x-www-form-urlencoded
Accept: text/html,application/xhtml+xml

Server Response Headers:

HTTP/1.1 200 OK
Date: Sat, 14 Nov 2026 13:00:00 GMT
Server: Apache/2.4.58 (Win64) OpenSSL/3.1.3 PHP/8.2.13
Content-Type: text/html; charset=UTF-8
Connection: keep-alive

3. HTTP Status Code Taxonomy

1xx Informational

Request received, continuing process (e.g. 101 Switching Protocols).

2xx Success

Action successfully received and accepted (e.g. 200 OK, 201 Created).

3xx Redirection

Further action required to fulfill request (e.g. 301 Moved Permanently, 304 Not Modified).

4xx Client Error

Request contains bad syntax or unauthorized access (e.g. 400 Bad Request, 404 Not Found).

5xx Server Error

Server failed to fulfill a valid request (e.g. 500 Internal Server Error, 502 Bad Gateway).

4. Statelessness & Session Handling

HTTP is fundamentally stateless: the server retains no memory of previous requests from the same client. To maintain booking sessions, web applications utilize Set-Cookie headers containing session IDs, which the client re-transmits in subsequent Cookie: PHPSESSID=... headers.
